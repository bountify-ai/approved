# Get Approved private browser demo

The public demo runs the pinned approval.md core daemon, the scripted agent in
`demo/agent/agent.py`, a simulated browser messaging transport, and the live advisory judge.
Visitors do not need Telegram or a local checkout. The browser transport is a demo component;
approval decisions and the append-only log come from the real core runtime.

The `approved-demo-gateway` Vercel origin serves its public static `/` page and forwards only
the listed API routes to the Maritime backend. The backend's own static `/` response still
requires gateway authentication. The gateway injects `X-Approved-Gateway` from its private configuration. Direct calls to
the shared Maritime origin require that secret on every route except `GET /health`. The backend
accepts `TRYIT_GATEWAY_SECRET` or `TRYIT_GATEWAY_SECRET_FILE` (at least 32 characters; exactly
one). Neither the gateway nor the backend puts visitor capabilities in URLs or cookies.

`POST /api/session` with `Content-Type: application/json` and `{}` reserves one of two runtime
slots and returns immediately with a `session_token` shown only in that response and lifecycle state `starting`.
The browser holds that capability in `sessionStorage` and sends it as `X-Approved-Session` to
every other data, run, reset, and tap route. `GET /api/state` exposes lifecycle state
`starting`, `ready`, `failed`, or `expired`, an expiry timestamp, retryability, and a message.
Once ready, it also returns the run, reviewer, health, and record views. Expired capabilities
answer 410 and cannot be used again. Capacity exhaustion answers 429. The static `/` page
requires only the gateway credential. `GET /health` is the sole unauthenticated route.

A session has its own `/data/tryit/sessions/<random-id>/demo` store and approval log, judge
state, generated credentials, and daemon, fake Telegram, judge, and agent process groups.
Each active slot uses a distinct set of internal loopback ports. A 15-minute expiry revokes the
visitor capability, ends its run, terminates only its own processes, and releases the slot
after cleanup. The log and store remain on disk; a later session receives a new random id and
never reads those files. `POST /api/reset` clears only the browser-visible run and chat floor.
The core's fixed policy and agent scenarios cannot be changed by visitor input.
The core's Telegram bot ownership registry is also rooted in each session's data directory;
a later visitor can safely reuse a slot's fake Bot API port without inheriting the previous
visitor's bot claim.
GET /api/policy reads only the current session's fixed APPROVAL.md file after readiness,
returning bounded UTF-8 text, its actual VPS path, and the SHA-256 of the current bytes.
This view is not a statement about historic attestation; no caller-supplied path is accepted.

`POST /api/run` starts one scripted run in that session. `GET /approver/api/chat` shows its
private demo messages; `POST /approver/api/tap` delivers an Approve or Reject button only for a
prompt opened by the current run, at most once. Human decisions still work if the judge fails;
the state shows the missing advisory. An exhausted live budget refuses another paid run with
`budget-exhausted`; an unreadable spending ledger returns `budget-unavailable`. No offline
reviewer is substituted into a live demo.

The live reviewer key goes only to judge children. The backend creates a durable shared
inference-call ledger in `/data/tryit/inference-calls.json` before a judge can start. The judge
reserves every actual SDK attempt, including retries, against the lifetime and hourly caps.
The coarser run budget in `/data/tryit/live-budget.json` reserves four logical reviews per run
across both sessions. Defaults are 80 calls lifetime and per UTC day, and 20 per rolling hour;
all three configuration knobs have hard upper bounds at those values:
`TRYIT_LIVE_LIFETIME_CAP`, `TRYIT_LIVE_DAILY_CAP`, and
`TRYIT_LIVE_CALLS_PER_HOUR`. The inference key and `REVIEWER_MODEL` must be configured with
`TRYIT_LIVE=1`; the backend refuses to boot without live configuration. Corrupt or missing
initialized budget files fail closed for new paid calls.

`images/tryit/Dockerfile` builds the backend and pinned runtime. For local validation use
`make tryit-smoke`; the image smoke exercises two real daemons, gateway and session authority,
cross-session tap isolation, human decisions, distinct persistent logs, and core chain
verification under a 2 GB/1 CPU container limit. Session expiry and cleanup races are covered
by service unit tests. The image is published through a dedicated deployment branch
(the helper's default is `deploy/tryit`), generated by `make tryit-deploy-branch`; it is never the root judge
Dockerfile on `main`. `images/daemon/entrypoint.mjs` has one narrow optional
`APPROVAL_WEBHOOK_INTERNAL_PORT` setting so the two session daemons can coexist; its default
behavior remains the upstream daemon behavior.

For a local backend using a real reviewer, export `TRYIT_GATEWAY_SECRET` (at least 32
characters), `WANDB_API_KEY`, and `REVIEWER_MODEL`, then run `make tryit`. Send
`X-Approved-Gateway` in every request except `/health`. `make tryit` does not start the
dedicated gateway; `make demo` is the offline local comparison.
